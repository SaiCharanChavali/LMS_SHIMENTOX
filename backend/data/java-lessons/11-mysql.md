## Introduction to MySQL
**MySQL** is one of the most widely used open-source relational databases. It powers web applications from small blogs to very large platforms and is the default choice in many Java/Spring Boot projects. Its default storage engine, **InnoDB**, supports transactions, foreign keys and row-level locking.

## Installation
1. Download **MySQL Community Server** for your OS (Windows users can use the MySQL Installer, which also installs Workbench). On macOS use the DMG or `brew install mysql`; on Ubuntu `sudo apt install mysql-server`. Docker users can run `docker run --name mysql -e MYSQL_ROOT_PASSWORD=secret -p 3306:3306 -d mysql:8`.
2. During setup choose a strong **root password** and keep the default port **3306**.
3. Verify from a terminal:

```bash
mysql --version
mysql -u root -p          # prompts for the password, opens the mysql> shell
```

Inside the shell:

```sql
SHOW DATABASES;
SELECT VERSION();
EXIT;
```

### Create an application user
Never connect your application as `root`. Create a user with only the privileges it needs:

```sql
CREATE USER 'lms_app'@'localhost' IDENTIFIED BY 'Str0ng!Passw0rd';
GRANT SELECT, INSERT, UPDATE, DELETE ON training_db.* TO 'lms_app'@'localhost';
FLUSH PRIVILEGES;
```

## MySQL Workbench
**MySQL Workbench** is the official graphical tool. With it you can:
- Create saved **connections** (host, port, user) and open SQL editor tabs.
- Browse schemas, tables and columns in the Navigator panel.
- Run queries (lightning-bolt icon or Ctrl+Enter for the current statement) and view results in a grid.
- Design tables with a form instead of typing DDL.
- Draw **EER diagrams** and reverse-engineer an existing database into a diagram.
- Inspect query plans (Explain) and server status.
- Export and import data (Server → Data Export / Data Import).

Other good clients: DBeaver, the IntelliJ IDEA Database tool, and the command-line `mysql` client.

## Creating databases and tables
```sql
CREATE DATABASE IF NOT EXISTS training_db
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE training_db;

CREATE TABLE trainer (
    id          INT AUTO_INCREMENT PRIMARY KEY,
    full_name   VARCHAR(100) NOT NULL,
    email       VARCHAR(150) NOT NULL UNIQUE,
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;

CREATE TABLE course (
    id           INT AUTO_INCREMENT PRIMARY KEY,
    code         VARCHAR(20)  NOT NULL UNIQUE,
    title        VARCHAR(150) NOT NULL,
    fee          DECIMAL(10,2) NOT NULL DEFAULT 0 CHECK (fee >= 0),
    level        ENUM('BEGINNER','INTERMEDIATE','ADVANCED') DEFAULT 'BEGINNER',
    trainer_id   INT,
    published    BOOLEAN DEFAULT FALSE,
    CONSTRAINT fk_course_trainer FOREIGN KEY (trainer_id)
        REFERENCES trainer(id) ON DELETE SET NULL
) ENGINE=InnoDB;

SHOW TABLES;
DESCRIBE course;
```

Useful MySQL data types:

| Type | Use |
| --- | --- |
| `INT`, `BIGINT` | Whole numbers, IDs |
| `DECIMAL(p,s)` | Money - exact, never `FLOAT` for currency |
| `VARCHAR(n)` / `TEXT` | Short / long text |
| `DATE`, `DATETIME`, `TIMESTAMP` | Dates and times (`TIMESTAMP` is stored in UTC) |
| `BOOLEAN` | Alias of `TINYINT(1)` |
| `ENUM(...)` | One value from a fixed list |
| `JSON` | Semi-structured data with JSON functions |

Use `utf8mb4` so names and emoji in every language are stored correctly. Changing a table later: `ALTER TABLE course ADD COLUMN duration_hours INT;`, `ALTER TABLE course MODIFY title VARCHAR(200) NOT NULL;`, `ALTER TABLE course DROP COLUMN published;`.

## CRUD in MySQL
```sql
INSERT INTO trainer (full_name, email) VALUES ('Kiran Rao', 'kiran@corp.com');
SELECT LAST_INSERT_ID();                         -- id generated by AUTO_INCREMENT

INSERT INTO course (code, title, fee, level, trainer_id)
VALUES ('JAVA101', 'Java Basics', 4999, 'BEGINNER', 1),
       ('SPR201', 'Spring Boot', 7999, 'INTERMEDIATE', 1);

SELECT code, title, fee FROM course WHERE level = 'BEGINNER';
UPDATE course SET published = TRUE WHERE code = 'JAVA101';
DELETE FROM course WHERE code = 'SPR201';

-- Insert or update in one statement ("upsert")
INSERT INTO course (code, title, fee) VALUES ('JAVA101', 'Java Basics', 5499)
ON DUPLICATE KEY UPDATE fee = VALUES(fee);
```

MySQL Workbench runs in **safe update mode** by default, refusing `UPDATE`/`DELETE` without a key in `WHERE` - a useful guard.

## Indexes in MySQL
```sql
CREATE INDEX idx_course_level ON course(level);
CREATE INDEX idx_course_trainer_level ON course(trainer_id, level);
SHOW INDEX FROM course;

EXPLAIN SELECT * FROM course WHERE trainer_id = 1 AND level = 'BEGINNER';
DROP INDEX idx_course_level ON course;
```

In `EXPLAIN` output, check `type` (`ALL` means a full table scan, `ref`/`range`/`const` are better), `key` (the index chosen) and `rows` (estimated rows read). InnoDB stores rows ordered by primary key (the **clustered index**); secondary indexes point back to the primary key, so keep primary keys short. `FULLTEXT` indexes support natural-language search on text columns.

## Aggregation
```sql
SELECT level,
       COUNT(*)            AS courses,
       ROUND(AVG(fee), 2)  AS avg_fee,
       MAX(fee)            AS max_fee
FROM course
GROUP BY level
HAVING COUNT(*) >= 1
ORDER BY avg_fee DESC;

-- Subtotals and a grand total
SELECT level, SUM(fee) FROM course GROUP BY level WITH ROLLUP;

-- Comma-separated list per group
SELECT t.full_name, GROUP_CONCAT(c.code ORDER BY c.code SEPARATOR ', ') AS courses
FROM trainer t LEFT JOIN course c ON c.trainer_id = t.id
GROUP BY t.id, t.full_name;
```

MySQL 8 also supports window functions (`ROW_NUMBER()`, `RANK()`, `SUM() OVER (...)`) and common table expressions (`WITH ... AS (...)`), which make reports much easier to read.

## Backups and operations basics
- Export a database: `mysqldump -u root -p training_db > training_db.sql`
- Restore it: `mysql -u root -p training_db < training_db.sql`
- Test restores regularly - a backup you have never restored is not proven.
- Keep credentials out of source code (environment variables or a secrets manager).

## Common mistakes
- Using `root` from the application.
- Storing money as `FLOAT`/`DOUBLE`.
- Using the legacy `utf8` charset instead of `utf8mb4`.
- Forgetting `ENGINE=InnoDB` on very old servers (no transactions with MyISAM).
- Adding indexes without checking `EXPLAIN`.

2. Create `trainer`, `course`, `employee` and `enrollment` tables with keys and constraints.
3. Insert at least 5 courses and 10 enrollments.
4. Write queries: courses per level, average fee per trainer, employees enrolled in more than two courses.

## Key takeaways
- MySQL with InnoDB provides transactions, foreign keys and row-level locking.
- Use Workbench (or another client) to explore schemas, run queries and draw diagrams.
- Choose correct types: `DECIMAL` for money, `utf8mb4` for text, `AUTO_INCREMENT` keys.
- Verify index use with `EXPLAIN`.
- Use a least-privilege application user and test your backups.
